## Key implementation decisions
- **Codec, not reducer.** `ProtocolCodec.encodeState` gets `latestPhoneVersion: String? = null`. A non-blank value (after `trim` and removing one leading `v`) ORs `PHONE_UPDATE_AVAILABLE_MASK` into FLAGS and adds key 14 on all three state messages; null, blank or a bare `v` leaves both out. `encodeCompatibilityError` is unchanged.
- **Provider read per send.** `NavigationController` takes `latestPhoneUpdate: () -> String? = { null }` and reads it on every `SendState`. `AppContainer` supplies the update check's latest version while `updateAvailable`.
- **Staleness.** `lastCheckMillis` is a `StateFlow` seeded from the existing `last_check_millis` and updated when a check records its attempt, failed or not. A throttled (skipped) check does not move it. `isCheckStale` makes no network call.
- **Dashboard.** `updatePrompt(stale, autoCheckEnabled, staleCheckFinished)` picks NONE, STALE_CHECK or WEEKLY_QUESTION. `MainActivity` keeps `staleCheckFinished` in `rememberSaveable`; it is not persisted. After a check started from the stale card, it becomes true only if weekly checks are off. **Turn on** calls `setAutoCheckEnabled(true)` without a second check, since one just ran. `PromptCard` gained an optional second (text) button. The stale card has two bodies ("never checked" and "over 30 days").
- **Watch persistence.** Keys 17 and 18 are written only on change. An emptied key 17 is removed with `persist_delete`. Write and read failures are logged with `APP_LOG`. Only messages that carry FLAGS update the record, so the compatibility error leaves it alone.
- **Notice window.** It is created once and reused if a newer version brings the notice back in the same session. It is freed in `deinit`. UP, SELECT, DOWN and BACK are subscribed on the notice window, so a press only closes it. `update_notice_window_push` returns false if the notice is already open or cannot be created, and then the version is not marked shown.
- **Round message layout (not in the plan).** On chalk the five-line update idle text clipped at the bezel. `main.c` now picks the message font on round screens against the circle (`fit_round_message`: measure, inset to the narrowest row the block spans, measure again). Rectangular screens keep their exact previous geometry. On chalk, long messages, the usual idle text included, now use a smaller font than before.

2. The plan asked for one test class per area. One extra test was added: `NavigationControllerTest.everySendReadsTheLatestPhoneUpdate`.
3. The round-screen message font fit in `main.c` (see above) was not planned. It was needed for NFR4 on chalk.
4. The notice window is created once and reused rather than created per push.
5. `update_notice_window.h` also exposes `update_notice_window_is_open` and `update_notice_window_deinit`.
